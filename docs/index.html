OCR Sanchaya

Browser-based OCR for Kannada & 14+ Indic Languages — Codebase Documentation

Introduction

OCR Sanchaya is a browser-based Optical Character Recognition application focused on Kannada and other Indic scripts. All OCR processing runs entirely in the browser via Tesseract.js (WebAssembly). The backend server is optional and only provides storage for research data.

The project contains two frontend variants:

  • Vue 3 SPA (ocr-kannada/) — Full-featured with TinyMCE editor, styled HTML preservation (bold/italic/size from OCR word data), spellcheck, word diff, PDF pagination, multi-format export
  • Static HTML (index.html) — Simple, no-build-required version served directly by Flask

App.vue — Core Features

OCR Recognition

doOCR() — Runs Tesseract.js on the displayed image. doOCRAllPages() — Batch-processes multi-page PDFs; page 1 appears in editor immediately while remaining pages process in background.

Styled Rich Text Editor

TinyMCE integration with Kannada spellcheck (via spell.toolforge.org). Page 1 OCR text appears as soon as it completes. Bold, italic, and font sizes from Tesseract.js word data are preserved as styled HTML via generateStyledHtml().

Word Diff

onTextChange() — Tracks added/removed words when user edits OCR output. Shows green (added) and red (removed) panels.

Multi-Format Export

TXT, DOCX, hOCR, HTML layout (with preserved styling), and TSV export. HTML layout uses styledHtml when available for richer output. Full-screen viewer for raw hOCR/HTML/TSV data.

Tesseract.js Integration

const result = await Tesseract.recognize(imgSrc, language, { logger });
// logger provides real-time progress: { status: "recognizing", progress: 0.45 }
const paragraphs = result.data.paragraphs.map(p => p.text.trim());
const text = paragraphs.join('\n\n');

tesseract-ocr.js — Key Functions

  • processPDF(file) — Loads PDF with pdfjsLib, renders each page to canvas at 1.5x scale, runs OCR on all pages with Promise.all
  • recognizeFile(file) — Creates Tesseract.TesseractWorker with WASM or ASM.js core, runs recognition with progress callbacks
  • progressUpdate(packet) — Renders real-time OCR progress in the #log div
  • exportTxt / exportDocx — Client-side file download

Core Path Selection

const corePath = window.navigator.userAgent.indexOf("Edge") > -1
  ? 'js/tesseract-core.asm.js'
  : 'js/tesseract-core.wasm.js';

ImageLoader Component

src/components/ImageLoader.vue (340 lines) handles all file input for the Vue app.

Input Methods

  • Drag & Drop — @dragover, @dragleave, @drop with visual feedback
  • File Picker — Hidden <input type="file"> triggered by styled label
  • Clipboard Paste — document.onpaste event handler

PDF Processing Flow

1. file.arrayBuffer() → pdfjsLib.getDocument({ data })
2. pdf.getPage(n) → page.render({ canvasContext, viewport })
3. canvas.toDataURL("image/png") → pageImages[] 
4. emit("pdf-loaded", { totalPages, pageImages })

Emits

  • pdf-loaded — Total pages + array of page image data URLs
  • page-ready — Individual page progress
  • file-loaded — Raw File object (for server upload)

Tesseract.js Integration

Both frontends use Tesseract.js v5.x. The OCR engine runs entirely in the browser via WebAssembly.

Key Details

  • Language data: Downloaded on first use (~4MB per language), cached in browser
  • Worker model: Separate worker thread for non-blocking OCR
  • Progress: Real-time logger callback with status and progress (0–1)
  • Supported: 16 languages via language codes

Vue App (v5 API)

import Tesseract from "tesseract.js";
const result = await Tesseract.recognize(imgSrc, "kan+eng", {
  logger: m => { console.log(m.status, m.progress); }
});

Static App (legacy v2/v4 API)

const worker = new Tesseract.TesseractWorker({ corePath: '...' });
worker.recognize(file, "kan")
  .progress(packet => progressUpdate(packet))
  .then(data => progressUpdate({ status: 'done', data }));

File Naming

def generate_unique_filename(original_filename):
    ext = get_file_extension(original_filename)
    timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
    short_hash = hashlib.md5(str(uuid.uuid4()).encode()).hexdigest()[:8]
    return f"{timestamp}_{short_hash}{ext}"
# Example: "20260518_183022_a1b2c3d4.png"

Data Retention

The server keeps the last 1000 OCR result entries in ocr_results.json. Each entry stores: id, timestamp, client IP, user agent, language, engine, file_id, text (first 500 chars), text_length, word_count.

Data Flow

OCR Recognition

User selects image/PDF
       │
       ▼
ImageLoader.vue / index.html  →  Loads file, renders to canvas/data URL
  For PDF: renders each page via pdfjsLib
       │
       ▼
Tesseract.js  →  Client-side OCR in browser (WASM)
  recognize(image, lang)  →  Downloads language data (~4MB first use)
       │
       ▼
extractPageData + generateStyledHtml
  → text (plain), hocr, tsv, styledHtml (rich HTML with bold/italic/size)
       │
       ▼
App.vue  →  setEditorContent() polls TinyMCE until ready, sets styled content
  Progress shown via logger callback
  Page 1 appears immediately; remaining pages continue in background
       │ (optional)
       ▼
Flask Server  →  POST /api/upload & POST /api/save-text
  Saves to /texts/{uuid}.txt
  Logs metadata to research/ocr_results.json

Word Diff

User edits text in TinyMCE
       │
       ▼
onTextChange() splits original & current text into word sets
       │
       ├── Added words (green)  ← in new, not in original
       └── Removed words (red)  ← in original, not in new

Optional: corrected version saved to server via /api/save-text

Design Decisions

  1. Client-side OCR — All recognition runs in browser. Zero server load. Offline-capable after initial language data download.
  2. Two frontends — Static HTML (no build) vs Vue 3 SPA (richer editor).
  3. Optional server — Backend is optional. Frontends work standalone.
  4. Research focus — Server collects metadata (language, engine, IP) alongside OCR text for accuracy research.
  5. Default language: kan+eng — Kannada + English selected by default for mixed-script documents.
  6. Styled editor content — Word-level bold, italic, and font-size from Tesseract.js preserved as HTML tags in TinyMCE; invalidated on user edit.
  7. Poll-based editor readiness — setEditorContent() polls TinyMCE up to 30 times to handle race condition where OCR completes before editor initialization.
